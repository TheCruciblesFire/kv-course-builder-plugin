# Interaction Evaluation Output Templates

Use these templates when evaluating whether material should become an interaction.

## Standard Template

```markdown
# Interaction Evaluation

## Source Material
- **Source type:** [lesson / sermon section / packet section / devotional concept / study material / other]
- **Intended learner / audience:** [known or unspecified]
- **Controlling passage or source, if any:** [passage, source, or unspecified]
- **Known platform or delivery context:** [known or unspecified]
- **Evaluation limits:** [missing inputs, source concerns, or none]

## Recommendation
**Decision:** [Yes / Optional / No]  
**Strength:** [Strong / Moderate / Light]  
**Primary reason:** [one concise reason]

## Learner Action
[What the learner would actually do. If none, say so.]

## Learner Friction
[What the learner needs help seeing, sorting, practicing, discerning, remembering, or applying.]

## Tone and Sensitivity Check
[State whether interactivity fits the tone. Recommend reflection, prayer, discussion, or teaching if interaction would trivialize the material.]

## Best Format
**Recommended format:** [broad interaction type or non-interactive alternative]  
**Why this fits:** [brief rationale]  
**Estimated time:** [brief estimate when useful, or unspecified]  
**Complexity level:** [Low / Moderate / High, with one sentence]  
**Adult micro-learning fit:** [Strong / Moderate / Weak, with one sentence]  
**Avoid:** [mechanics, tone, or output types to avoid]

## Source / Faithfulness Cautions
- [source transparency issue, passage faithfulness issue, answer-key risk, or none]
- If example statements, answer options, feedback text, or final activity items were not supplied in final form, use conditional wording. Example: `If included, this claim should be checked before becoming learner-facing feedback.`

## Better Non-Interactive Alternative
[Use when the decision is Optional or No.]

## Build Recommendation
[Proceed toward activity design / keep as reflection / keep as teaching / run passage-faithfulness check first / clarify sources before building.]

If any source material, statement list, answer logic, platform constraint, or passage-faithfulness check remains unsettled, include this boundary explicitly: `Do not build the learner-facing activity yet.`
```

## Compact Template

Use this for narrow checks.

```markdown
**Decision:** [Yes / Optional / No]

**Why:** [brief reason]

**Best format:** [broad interaction type or non-interactive alternative]

**Do not build as:** [formats to avoid]

**Next step:** [decision, check, or downstream workflow. If checks remain, say not to build the learner-facing activity yet.]
```

## Decision Language

Use clear decision language:

- **Yes - interaction recommended** when active processing is instructionally warranted.
- **Optional - interaction may help** when interactivity could support learning but is not essential.
- **No - keep non-interactive** when teaching, reflection, prayer, or discussion is better.

Do not present the recommendation as a finished activity.

## Example Tightened Build Recommendation

Use wording like this when the material is a good interaction candidate but the exact statement list or answer logic has not been reviewed:

```markdown
Proceed toward activity design, but do not build the learner-facing activity yet.

First, finalize the statement list. Then run a passage-faithfulness check on each statement and proposed category label. After that, this may be built as a bounded claim-support sorting activity.

**Estimated time:** 3-5 minutes.

**Complexity level:** Moderate. Best with 6-9 statements and three clear categories.

**Adult micro-learning fit:** Strong, if feedback is concise, sober, and focused on discernment rather than game mechanics.
```
